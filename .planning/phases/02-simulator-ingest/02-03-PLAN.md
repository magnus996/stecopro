<task type="auto">
  <name>Task 1: Implement runBackfill in runner.ts</name>
  <files>src/lib/simulator/runner.ts</files>
  <action>
    Create `runner.ts` exporting `runBackfill(adapter: IngestAdapter, ctx: SimContext, opts?: { daysBack?: number; now?: Date })`.

    `SimContext` carries the resolved ids the script discovered: `{ plantId, machineIds: { bunker: number; conveyor: number; press: number }, fractionIds: Record<string, number> }` (fraction name → id, covering Deink, Tetra/emballasjepapp, OCC, Miks).

    Logic:
    - daysBack defaults to 14; `now` defaults to `new Date()`.
    - For each of the last `daysBack` Oslo calendar days, for each shiftType ('day','evening'):
      - Compute UTC bounds via `getShiftBoundsUtc` (from time.ts). Skip shift windows whose start is in the future relative to `now` (so a mid-day run doesn't fabricate the rest of today's evening shift).
      - `const shiftId = adapter.ensureShift(plantId, shiftType, startAt, endAt)`.
      - Seed the engine deterministically from the shift start day (e.g. `Math.floor(startMs / 86400000)` combined with shiftType).
      - `const events = simulateShift({ ...bounds, seed, machine/bale params from SimContext })`.
      - Walk events in order, translating each to an adapter call:
        - 'reading' → `adapter.reportReading(machineIds[machineKey], at, currentA, runState)`
        - 'stop' → `const id = adapter.reportStop(plantId, at, reason, stopType)`; remember the open id
        - 'stopEnd' → `adapter.reportStopEnded(openStopId, at)`
        - 'bale' → `adapter.reportBale(plantId, fractionId, machineIds.press, at)` (map the engine's abstract fraction index to the real fractionId via SimContext)
    - Call `adapter.flush()` after each shift (or once at the end) to write buffered readings.

    The engine emits abstract machine/fraction indices; the runner owns the index→real-id mapping. Keep runner free of `new Database()` — it only uses the injected adapter, so live mode (plan 04) can reuse it. Export `SimContext` and a helper `advanceLiveTick(adapter, ctx, now)` that simulates only the single most-recent minute (plan 04 will call it on an interval) — OR leave the live tick to plan 04; if you stub it, keep it pure and documented. Prefer implementing `runBackfill` fully; `advanceLiveTick` may be a thin wrapper that runs the current minute of the current shift.
  </action>
  <verify>`npx tsc --noEmit` passes. `grep -n "simulateShift" src/lib/simulator/runner.ts` matches. `grep -n "new Database" src/lib/simulator/runner.ts` returns nothing (runner must not open its own connection).</verify>
  <done>runBackfill walks 14 days of shifts, maps every SimEvent type to the correct adapter method, never opens a DB connection, and flushes buffered readings; tsc passes.</done>
</task>

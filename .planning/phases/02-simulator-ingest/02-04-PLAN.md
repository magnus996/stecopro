<objective>
Make the plant keep moving during a demo: while `npm run dev` runs, the simulator emits new readings/stops/bales in near-real time so the dashboard (Phase 3) animates.

Live mode reuses the same engine and adapter as backfill (no duplicated simulation logic). It is hosted from `src/instrumentation.ts`, whose `register()` runs once per Node.js server bootstrap. A `NEXT_RUNTIME === 'nodejs'` check plus a `globalThis.__SIMULATOR_STARTED__` once-guard prevent edge-runtime execution and HMR double-starts (02-RESEARCH.md Pitfall 3, issue #51450). `live.ts` opens its OWN WAL connection (not `@/db/index`, which is server-only), resolves the plant/machine/fraction ids, catches up any gap since the last stored reading (read `MAX(recordedAt)`), then `setInterval`s a one-minute tick.

Purpose: SIMU-08 (live mode keeps producing data so the dashboard moves).
Output: `live.ts`, `instrumentation.ts`, a `next.config.ts` instrumentation enablement if required, and `scripts/verify-live.sh`.
</objective>

  <action>
    Create `src/instrumentation.ts` (the project uses the src/ layout, so it lives in src/):

    ```typescript
    export async function register() {
      if (process.env.NEXT_RUNTIME !== 'nodejs') return
      if ((globalThis as { __SIMULATOR_STARTED__?: boolean }).__SIMULATOR_STARTED__) return
      ;(globalThis as { __SIMULATOR_STARTED__?: boolean }).__SIMULATOR_STARTED__ = true
      const { startLive } = await import('./lib/simulator/live')
      startLive()
    }
    ```

    The dynamic import keeps the simulator out of the edge bundle. The NEXT_RUNTIME guard ensures it only runs on the Node.js server. The globalThis flag prevents HMR re-execution from starting a second interval (Pitfall 3 / issue #51450).

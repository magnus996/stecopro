  <name>Task 1: Define the IngestAdapter interface</name>
  <files>src/lib/ingest/interface.ts</files>
  <action>
    Create the `IngestAdapter` TypeScript interface — the contract the simulator implements now and an OPC UA adapter implements later. This is the surface defined in 02-RESEARCH.md Pattern 1. Use these exact method signatures (English code/comments per project rules; the strings the engine passes will be Norwegian):

    ```typescript
    export type StopType = 'fault' | 'idle' | 'planned'
    export type ShiftType = 'day' | 'evening'

    export interface IngestAdapter {
      /** Record one minute of motor current draw for a machine. runState: true=running, false=stopped. */
      reportReading(machineId: number, recordedAt: Date, currentA: number, runState: boolean): void

      /** Plant-level stop begins. Returns the new stop_events row id. reason is an HMI string (Norwegian). */
      reportStop(plantId: number, startAt: Date, reason: string, stopType: StopType): number

      /** Close an open stop_events row by id. */
      reportStopEnded(stopEventId: number, endAt: Date): void

      /** One completed bale. machineId is the press (nullable allowed). weightKg optional. */
      reportBale(plantId: number, fractionId: number, machineId: number | null, occurredAt: Date, weightKg?: number): void

      /** Idempotently upsert a shift row; returns its id. */
      ensureShift(plantId: number, shiftType: ShiftType, startAt: Date, endAt: Date): number

      /** Flush any buffered writes (no-op for adapters that write immediately). */
      flush(): void
    }
    ```

    Map StopType/ShiftType to the schema's text columns (stop_events.stopType, shifts.shiftType). Do NOT add query methods — the interface is write-only. Export `StopType` and `ShiftType` for reuse by the engine and adapter.
  </action>

<task type="auto">
  <name>Task 2: Implement SqliteIngestAdapter with batched readings</name>
  <files>src/lib/ingest/sqlite-adapter.ts</files>
  <action>
    Create `SqliteIngestAdapter` implementing `IngestAdapter`. It receives a Drizzle db instance in its constructor (so both the backfill script and live runner can pass their own connection) plus the tenantId it writes as:

    ```typescript
    constructor(private db: BetterSQLite3Database<typeof schema>, private tenantId: number) {}
    ```

    Use `import type { BetterSQLite3Database } from 'drizzle-orm/better-sqlite3'` and `import * as schema from '@/db/schema'`. Do NOT import `@/db/index` — it is `server-only` and throws outside the Next.js request context (see 02-RESEARCH.md Pitfall 1). The caller provides the db.

    Implementation details:
    - `reportReading`: buffer into a private `pendingReadings: typeof schema.timeSeriesReadings.$inferInsert[]` array (push `{ tenantId, machineId, recordedAt, currentA, runState }`). Do not write per call — buffering keeps backfill fast.
    - `flush`: if buffer non-empty, wrap inserts in `this.db.transaction(() => { ... })()` inserting all pending readings, then clear the buffer. This is the 25ms/40k-row pattern from research.
    - `reportStop`: `db.insert(schema.stopEvents).values({ tenantId, plantId, startAt, endAt: null, reason, stopType }).returning().all()` and return the inserted row's `id`.
    - `reportStopEnded`: `db.update(schema.stopEvents).set({ endAt }).where(eq(schema.stopEvents.id, stopEventId)).run()`.
    - `reportBale`: `db.insert(schema.baleEvents).values({ tenantId, plantId, fractionId, machineId, occurredAt, weightKg }).run()`.
    - `ensureShift`: query for an existing shift with same plantId+shiftType+startAt; if found return its id, else insert and return new id (idempotent so re-running backfill or live catch-up doesn't duplicate shifts).

    Import `eq`, `and` from `drizzle-orm`. Keep readings buffered but write stops/bales/shifts immediately (they are low-volume and the engine needs the returned stop id synchronously).
  </action>
  <verify>Run `npx tsc --noEmit` — no errors. Run this inline smoke test: `npx tsx -e "import Database from 'better-sqlite3'; import { drizzle } from 'drizzle-orm/better-sqlite3'; import * as schema from './src/db/schema'; const s=new Database(':memory:'); console.log('adapter import ok')"` to confirm imports resolve (full DB write is exercised by plan 03's backfill).</verify>
  <done>SqliteIngestAdapter implements all 6 IngestAdapter methods; reportReading buffers and flush writes in one transaction; tsc passes.</done>

<task type="auto">
  <name>Task 3: Add WAL pragmas to the app DB connection</name>
  <files>src/db/index.ts</files>
  <action>
    The live simulator (plan 04) writes to the same SQLite file the app reads from. Without WAL mode this causes intermittent `SQLITE_BUSY: database is locked` (02-RESEARCH.md Pitfall 2). Add these three pragmas immediately after the `new Database(...)` line in `src/db/index.ts`, before the `drizzle(...)` call:

    ```typescript
    sqlite.pragma('journal_mode = WAL')
    sqlite.pragma('busy_timeout = 5000')
    sqlite.pragma('synchronous = NORMAL')
    ```

    Preserve the existing `import 'server-only'` and the fresh-`Database()`-per-module-load pattern (do NOT reintroduce a globalThis singleton — Phase 1 decision: Turbopack worker threads don't share globalThis). This is the only change to this file.

<objective>
Build the pure, deterministic state-machine engine that decides — minute by minute — what the simulated plant is doing: running, stopped (with a Norwegian reason), or running empty. This is the realism core of the entire demo (STATE.md research flag: "Simulator realism drives the whole demo").

The engine is a TDD candidate: it is pure (no I/O), seeded, and its behavior is expressible as `expect(availability).toBeCloseTo(0.9)`. It emits a typed list of `SimEvent`s; the runner (plan 03) translates those into IngestAdapter calls. Keeping the engine I/O-free lets both backfill and live mode reuse it and lets us assert the hard requirements (~90% availability, idle≠fault, shift boundaries) without a database.

Purpose: SIMU-03 (14-day history shape: shifts, ~90% availability), SIMU-04 (stop distribution + HMI reasons), SIMU-05 (bunker-empty as idle), and the realism inputs for SIMU-06/07.
Output: `params.ts`, `time.ts`, `engine.ts`, and `engine.test.ts` proving the must-have truths.
</objective>

<feature>
  <name>Feature B: Params + seeded engine producing ~90% availability with idle≠fault (RED→GREEN→REFACTOR)</name>
  <files>src/lib/simulator/params.ts, src/lib/simulator/engine.ts, src/lib/simulator/engine.test.ts</files>
  <behavior>
    `params.ts` exports tuning constants from 02-RESEARCH.md "Realistic Parameter Values":
      - `FAULT_REASONS` (8 Norwegian strings incl. 'Driftsstans transportbånd', 'Papirbrudd i presse', 'Nødstopp aktivert', ...)
      - `IDLE_REASONS` = ['Bunker tom']
      - `PLANNED_REASONS` (3 Norwegian strings)
      - `STOP_DURATION_WEIGHTS`: bands [2-5,5-10,10-30,30-120] min with weights [0.40,0.30,0.20,0.10]
      - current ranges per machine type (bunker 35-50 full / 5-8 empty / 0 stopped; conveyor 25-35 / 0; press 60-90 peak / 15-20 idle / 0)
      - bale rates per fraction per shift (Deink ~45, OCC ~35, Tetra/emballasjepapp ~25, Miks ~15)
      - `TARGET_AVAILABILITY = 0.9`

    `engine.ts` exports:
      - `mulberry32(seed): () => number` (the 5-line PRNG from research — deterministic).
      - A `SimEvent` discriminated union: `{ type:'reading', machineId, at, currentA, runState }` | `{ type:'stop', at, reason, stopType }` | `{ type:'stopEnd', at }` | `{ type:'bale', fractionId, at }`. (machine/fraction are abstract indices the runner maps to real ids.)
      - `simulateShift(input): SimEvent[]` walking the shift minute-by-minute with a seeded rng. Per minute it decides running vs stop vs bunker-empty, emits a reading per machine, and emits bale events at the configured rate. Stops draw a reason+duration from the weighted distribution; bunker-empty (~15 min after last refill, 3-12 min) emits stopType='idle' with reason 'Bunker tom'. No SimEvent has a timestamp outside the shift window.

    Write tests FIRST. Assertions (these ARE the phase must-haves):
      1. AVAILABILITY: run a full 8h day shift; running-minutes / 480 is within 0.85-0.95 (i.e. 90% ±5pp). Compute from reading runState OR from total stop-minutes — assert explicitly.
      2. IDLE≠FAULT: at least one 'stop' event has stopType==='idle' with reason 'Bunker tom'; NO event has stopType==='fault' with reason 'Bunker tom'.
      3. STOP SPREAD: across the shift, more stops fall in the 2-10 min band than in the 30-120 band (realistic skew).
      4. BOUNDARIES: every SimEvent.at is >= shift start and < shift end.
      5. REASONS NORWEGIAN: every 'stop' event reason is in FAULT_REASONS ∪ IDLE_REASONS ∪ PLANNED_REASONS.
      6. DETERMINISM: simulateShift with the same seed twice yields deep-equal event arrays; different seeds differ.
  </behavior>
  <implementation>
    Tune the per-minute stop probability so expected stop-minutes ≈ 48/480 = 10% (research: ~8-10 stops/shift, weighted durations averaging ~5-6 min). If the availability test lands outside ±5pp, adjust the per-minute probability constant in params.ts (not the test). Use mulberry32 seeded from shift start day so runs are reproducible. Keep engine.ts pure — no DB, no Date.now(), no Math.random(); all randomness flows through the injected rng. REFACTOR step: extract any duplicated band-selection logic into a small helper, keep tests green.
  </implementation>

  <behavior>
The module exports a pure function and a constant. No DB access, no `server-only`, no Date.now() reliance for testability — accept `nowMs` as an explicit parameter (defaulting to `Date.now()`) so tests are deterministic.

Types:
```ts
export interface OeeStopInput {
  startAt: Date
  endAt: Date | null              // null = ongoing
  stopType: 'fault' | 'idle' | 'planned'
}
export interface OeeInput {
  shiftStart: Date
  shiftEnd: Date                  // planned window end (may be in the future for the current shift)
  nowMs?: number                  // default Date.now(); the moment "ongoing" stops and the current shift are measured up to
  stopEvents: OeeStopInput[]
  baleCount: number               // actual bales produced this shift
  nominalBalesPerShift: number    // bales at 100% availability across the full planned window
  qualityFactor?: number          // default QUALITY_FACTOR
}
export interface OeeResult {
  availability: number  // 0-1
  performance: number   // 0-1
  quality: number       // 0-1
  oee: number           // A * P * Q, 0-1
  plannedSeconds: number  // effective planned window so far (shiftStart..min(shiftEnd, now))
  runSeconds: number
  stopSeconds: number
  totalBales: number
}
export const QUALITY_FACTOR = 0.95
export function calculateOee(input: OeeInput): OeeResult
```

Behaviour rules (encode each as a test case BEFORE implementing):

1. plannedSeconds = (min(shiftEnd, now) - shiftStart) / 1000, floored at 0. For a current shift, this is elapsed-so-far, not the full 8h — OEE reflects the shift in progress.
2. Each stop's contribution = overlap of [startAt, endAt ?? now] with [shiftStart, min(shiftEnd, now)], in seconds. Stops entirely outside the window contribute 0. This clamping is the key correctness property (Pitfall 5 in RESEARCH).
3. stopSeconds = sum of clamped overlaps, then capped at plannedSeconds (never exceeds the window).
4. runSeconds = plannedSeconds - stopSeconds.
5. availability = plannedSeconds > 0 ? runSeconds / plannedSeconds : 0.
6. performance = let nominalAtRunTime = nominalBalesPerShift * (runSeconds / fullPlannedSeconds) where fullPlannedSeconds = (shiftEnd - shiftStart)/1000. performance = nominalAtRunTime > 0 ? min(baleCount / nominalAtRunTime, 1) : 0. (Performance scales nominal output by the run-time fraction of the FULL shift, then compares actual bales; capped at 1.)
7. quality = qualityFactor ?? QUALITY_FACTOR.
8. oee = availability * performance * quality.
9. idle, fault, and planned stops ALL reduce availability identically (per RESEARCH open-question 4 — bunker-empty idle counts against availability). stopType does not change the math; it is carried only for callers that want to label stops.

Test cases (input -> expected):
- Full shift, no stops, bales == nominal: availability=1, performance=1, quality=0.95, oee=0.95.
- Full shift, one 48-min stop (2880s) in an 8h (28800s) window: availability = (28800-2880)/28800 = 0.9.
- Ongoing stop (endAt=null) that started 10 min ago, now = shiftStart + 1h: plannedSeconds=3600, stopSeconds=600, availability=(3600-600)/3600 ≈ 0.8333.
- Stop that started BEFORE shiftStart and ends 5 min into the shift: only the 5-min in-window overlap counts.
- Stop fully before shiftStart: contributes 0.
- nowMs before shiftStart entirely (plannedSeconds<=0): availability=0, performance=0, oee=0 (no divide-by-zero, no NaN).
- baleCount=0 with run time: performance=0.
- baleCount above nominalAtRunTime: performance capped at exactly 1.
- qualityFactor override (e.g. 0.9) flows into quality and oee.
- Returned fields plannedSeconds/runSeconds/stopSeconds/totalBales are populated and consistent (runSeconds = plannedSeconds - stopSeconds; totalBales = baleCount).

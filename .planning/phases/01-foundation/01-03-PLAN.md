<objective>
Build the authentication and tenant-isolation core: jose stateless sessions, a server-only Data Access Layer whose every function derives tenantId from the session (TENA-02), the login/logout server actions verifying bcrypt passwords (TENA-01), the login page, and the Next.js 16 `proxy.ts` for optimistic route protection.

Purpose: This is the security boundary of the whole product. Getting tenant scoping right in the DAL (tenantId from session, never from caller) is the hardest thing to retrofit (STATE.md research flag) — it is enforced here once so every later phase inherits it.

Create `src/lib/session.ts` exactly per research Pattern 1 (01-RESEARCH.md lines ~108–159), `import 'server-only'` at top:
- `encrypt(payload)`, `decrypt(session)` using jose SignJWT/jwtVerify with HS256 and `process.env.SESSION_SECRET`.
- `createSession(payload)` sets an HttpOnly, SameSite=lax, path=/ cookie named `session`, 7-day expiry, `secure` only in production.
- `deleteSession()` deletes the cookie.
- decrypt returns null on any verify failure (do not throw).

Create `src/lib/dal.ts` per research Pattern 2 (01-RESEARCH.md lines ~167–191), `import 'server-only'` at top:
- `verifySession = cache(async () => {...})` reads the `session` cookie, decrypts it, and `redirect('/login')` if no `userId`. Returns the session payload.
- `getCurrentUser = cache(async () => {...})` — re-queries the users table by `session.userId` AND `session.tenantId`, returning safe fields (id, name, email, role, tenantId); used for nav/role decisions and to honor the `active` flag (research Pitfall 4 / Open Question 2).
- `getPlants = cache(async () => {...})` — example tenant-scoped accessor: `db.select().from(plants).where(eq(plants.tenantId, session.tenantId))`.
- CRITICAL: no DAL function takes `tenantId` as a parameter. tenantId always comes from `verifySession()`. This is the enforced tenant-isolation pattern (research Pitfall 2). Add a short comment block at the top of dal.ts stating this rule so future contributors follow it.
- Handle `system_admin`: getPlants for a system_admin may return all plants (no tenant filter) — guard with `if (session.role === 'system_admin')`. Keep it minimal; Phase 5 builds the full system-admin surface.

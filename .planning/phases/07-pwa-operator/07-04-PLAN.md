  <name>Task 1: Photo upload + tenant-scoped serving</name>
  <files>src/app/api/photos/route.ts, src/app/api/photos/[id]/route.ts</files>
  <action>
Both routes use `getApiSession()` from @/lib/api-auth (NOT verifySession — research pitfall #5). Use route handlers (NOT server actions) because server actions have a 1MB body limit and photos are up to 10MB (research arch #6).

POST src/app/api/photos/route.ts (REPT-04 upload):
- `const session = await getApiSession(); if (!session) return 401`.
- Parse multipart: `const form = await req.formData(); const file = form.get('file')` (a File/Blob). 400 if missing.
- Guard MIME: `file.type` must start with 'image/' → else 400 `{error:'not_an_image'}`.
- Guard size: `file.size > 10 * 1024 * 1024` → 400 `{error:'too_large'}` (10 MB cap).
- Write to disk: dir `./uploads/{session.tenantId}/`, filename `{crypto.randomUUID()}.{ext}` where ext derives from mime ('image/jpeg'→'jpg','image/png'→'png','image/webp'→'webp', fallback 'bin'). Use `import { mkdir, writeFile } from 'node:fs/promises'` and `import { join } from 'node:path'`; `await mkdir(dir, { recursive: true })`; `await writeFile(path, Buffer.from(await file.arrayBuffer()))`.
- Insert a photos row: { tenantId: session.tenantId, userId: session.userId, filePath: relativePath, mimeType: file.type, sizeBytes: file.size }. Use `import { db } from '@/db'` + drizzle insert .returning() to get id.
- Return `NextResponse.json({ id, ok: true }, { status: 201 })`.

GET src/app/api/photos/[id]/route.ts (REPT-04 tenant-scoped serving):
- Next 16 dynamic route: signature `(req: NextRequest, { params }: { params: Promise<{ id: string }> })`; `const { id } = await params`.
- `getApiSession()` → 401 if none.
- Select the photos row by id. If not found OR `photo.tenantId !== session.tenantId` → 404 (research arch #7: a foreign tenant must get 404, never the file). Same 404 hides existence cross-tenant.
- Read the file from disk (filePath). Return it as a Response with header `Content-Type: photo.mimeType` and `Cache-Control: private, max-age=3600`. Use `new NextResponse(buffer, { headers })` or `new Response(buffer, ...)`.
  </action>

POST src/app/api/stops/[id]/ack/route.ts (REPT-01, idempotent):
- `getApiSession()` → 401. `const { id } = await params` → stopEventId = Number(id) (400 if NaN).
- Verify the stop belongs to the tenant: select stop_events where id = stopEventId AND tenantId = session.tenantId → 404 if absent (tenant isolation).
- Insert into stop_acknowledgements { tenantId, stopEventId, userId: session.userId } with `.onConflictDoNothing()` so a repeat ack is a no-op (the unique(stopEventId,userId) index from 07-01 makes this idempotent — REPT-01). Return `{ ok: true }`.

POST src/app/api/stops/[id]/comments/route.ts (REPT-02):
- `getApiSession()` → 401. Resolve+validate the stop belongs to tenant (404 otherwise).
- Body JSON `{ comment?: string, correctedReason?: string, photoId?: number }`. ZOD rule (research): require comment OR correctedReason non-empty → 400 `{error:'comment_or_reason_required'}` if both empty/whitespace. Build the schema with a `.refine()`.
- If photoId given, verify that photo row exists AND tenantId === session.tenantId (else 400 — don't let a comment reference a foreign-tenant photo).
- If correctedReason given, also UPDATE stop_events.reason for that stop (scoped to tenant) so the corrected reason shows everywhere — research describes it as "korreksjon av stoppårsak". Keep the original comment row as the audit trail.
- Insert stop_comments { tenantId, stopEventId, userId, comment, correctedReason, photoId }. Return `{ ok: true, id }` 201.
- Also add GET on this route: return the comment thread for the stop (tenant-scoped) ordered by createdAt asc, joined to author name and photoId — the /stopp/[id] page can fetch it, and the E2E can assert the thread.

POST src/app/api/notes/route.ts (REPT-03):
- `getApiSession()` → 401. Body `{ content: string, photoId?: number, plantId?: number }`. Require non-empty content (400).
- Resolve plantId: if given, verify it belongs to session.tenantId; else default to the tenant's first plant. 400 if the tenant has no plant.
- Validate photoId tenant ownership if present (as above).
- Insert shift_notes { tenantId, plantId, userId: session.userId, content, photoId }. No shiftId — shift derived later from plantId+createdAt. Return `{ ok: true, id }` 201.

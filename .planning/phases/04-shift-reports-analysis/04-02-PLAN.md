  <action>
Create the shift list server component. No 'use client' (no charts here). It is auto-dynamic because
the DAL calls cookies() via verifySession (same as dashboard/page.tsx — no force-dynamic needed).

- `import { getCurrentUser, getPlants, getShiftReportList } from '@/lib/dal'`.
- Get `user = await getCurrentUser()`; if null return null. Get `plants = await getPlants()`,
  `plant = plants[0] ?? null`; if no plant render an empty-state card ("Ingen anlegg") matching
  the dashboard pattern.
- Default date range: full 14 days. Compute Oslo today via
  `new Intl.DateTimeFormat('en-CA', { timeZone: 'Europe/Oslo' }).format(new Date())`. Compute
  `from` as 14 days earlier — derive by `new Date(Date.now() - 14*24*3600*1000)` formatted the same
  way. Call `getShiftReportList(plant.id, from, to)`.
- Render a table (semantic <table>) with header columns: Dato, Skift, OEE, Tilgjengelighet,
  Oppetid, Stopp (antall), Stoppetid, Baler. Norwegian labels.
  - shiftType 'day' → "Dag", 'evening' → "Kveld".
  - Date column: format startAt as 'dd.MM.yyyy' Oslo (use Intl.DateTimeFormat('no', {timeZone:'Europe/Oslo', day,month,year})).
  - OEE: `(row.oee * 100).toFixed(1)` + ' %'. Tilgjengelighet: `(row.availability*100).toFixed(1)` + ' %'.
  - Oppetid %: `(row.uptimeRunSeconds / row.uptimePlannedSeconds * 100).toFixed(1)` + ' %' (guard /0).
  - Stoppetid: `Math.round(row.stopSeconds/60)` + ' min'.
  - Each row's Dato/Skift cell is a Next.js `<Link href={\`/reports/shifts/${row.id}\`}>`.
- Heading: `<h1>` "Skiftrapporter". Use the same card/border Tailwind classes as the dashboard
  (rounded-lg border border-zinc-200 bg-white dark:... ; table text-sm).
- Do NOT compute energy here (RESEARCH Pitfall 7 — energy query only on detail page).
- Convert all Date values to strings server-side before rendering (no Date objects in JSX is fine
  since this is a server component, but format them for display as above).

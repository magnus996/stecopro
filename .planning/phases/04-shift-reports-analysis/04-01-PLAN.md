  <name>Task 1: Shift list + shift detail accessors</name>
  <files>src/lib/dal.ts</files>
  <action>
Add two exported accessors at the end of src/lib/dal.ts. Follow the existing DAL rules exactly:
wrap in `cache(async (...) => {...})`, call `await verifySession()` first, and put
`eq(<table>.tenantId, session.tenantId)` in EVERY WHERE clause. Accept `plantId` as a normal
parameter; NEVER accept tenantId.

(1) `getShiftReportList(plantId: number, fromDate: string, toDate: string)`:
  - `fromDate`/`toDate` are Oslo 'YYYY-MM-DD' strings.
  - Derive UTC bounds: `const { startMs: fromMs } = getShiftBoundsUtc(fromDate, 'day')` and
    `const { endMs: toMs } = getShiftBoundsUtc(toDate, 'evening')`.
  - Run TWO SEPARATE queries (RESEARCH Pitfall 1 — combining stops+bales LEFT JOIN produces a
    cartesian product that inflates stopSeconds). Do NOT join stopEvents and baleEvents in one SELECT.
    - Query A: select all shifts in [fromMs, toMs] ordered by startAt DESC (reverse chronological
      for the list). Filter `eq(shifts.tenantId, session.tenantId)`, `eq(shifts.plantId, plantId)`,
      `gte(shifts.startAt, new Date(fromMs))`, `lte(shifts.startAt, new Date(toMs))`.
    - Query B: for those shifts, reuse the existing `getShiftStops`-style overlap logic per shift.
      Simpler and correct: after Query A, for each shift run the existing tenant-scoped stop fetch
      inline OR fetch all overlapping stops in one query and bucket them in JS by shift window.
      Bucket in JS: select stopEvents where tenant+plant match and startAt < toMs and
      (endAt IS NULL OR endAt > fromMs); then for each shift, filter stops overlapping
      [shift.startAt, shift.endAt) in JS.
    - Query C (bales per shift): select baleEvents in [fromMs, toMs] for tenant+plant, then bucket
      in JS by shift window (occurredAt in [shift.startAt, shift.endAt)). Count per shift.
  - For each shift, compute OEE via `calculateOee` (imported already) with
    `shiftStart: shift.startAt, shiftEnd: shift.endAt, nowMs: shift.endAt.getTime()` (historical
    shift is fully elapsed — RESEARCH Code Example), `stopEvents` mapped to {startAt, endAt, stopType},
    `baleCount` = total bales for that shift, `nominalBalesPerShift: NOMINAL_BALES_PER_SHIFT`,
    `qualityFactor: QUALITY_FACTOR`.
  - Return an array of `ShiftReportRow` objects:
    `{ id, shiftType, startAt, endAt, oee: number, availability: number, performance: number,
       uptimeRunSeconds, uptimePlannedSeconds, stopCount, stopSeconds, totalBales }`.
    (oee/availability/performance are the 0-1 fields straight from the OeeResult.)
  - Export a `ShiftReportRow` interface.

(2) `getShiftReportDetail(plantId: number, shiftId: number)`:
  - Fetch the single shift row with `eq(shifts.id, shiftId)`, `eq(shifts.tenantId, session.tenantId)`,
    `eq(shifts.plantId, plantId)`, `.limit(1)`. If not found → return null (RESEARCH Pitfall 6:
    shiftId is untrusted; tenant filter prevents cross-tenant access).
  - Reuse `getShiftStops(plantId, shift.startAt, shift.endAt)` for the stop list.
  - Reuse `getBaleCountsByFraction(plantId, shift.startAt, shift.endAt)` for bales per fraction.
  - Compute OEE via `calculateOee` with `nowMs: shift.endAt.getTime()` and total bales summed from
    the fraction rows.
  - Return `ShiftReportDetail`:
    `{ shift: { id, shiftType, startAt, endAt }, oee: OeeResult,
       stops: { startAt, endAt, reason, stopType }[],
       balesByFraction: { fractionId, name, count }[], totalBales }`.
  - Export a `ShiftReportDetail` interface.
  </action>

<task type="auto">
  <name>Task 2: Pareto, bales-per-day, day-vs-evening, and energy-proxy accessors</name>
  <files>src/lib/dal.ts</files>
  <action>
Add four more exported accessors to src/lib/dal.ts, same DAL rules (verifySession first,
tenantId only from session).

(1) `getParetoData(plantId: number, fromDate: string, toDate: string)`:
  - Oslo date bounds via getShiftBoundsUtc(from,'day').startMs and getShiftBoundsUtc(to,'evening').endMs.
  - Group stopEvents by `reason` and `stopType`; select `incidentCount: sql<number>\`count(*)\`` and
    `totalSeconds: sql<number>\`sum(coalesce(${stopEvents.endAt}, unixepoch()) - ${stopEvents.startAt})\``.
    NOTE: recordedAt/startAt/endAt are Unix seconds in SQLite (STATE.md), so the subtraction is in
    seconds — correct. Filter tenant+plant, `isNotNull(stopEvents.reason)`, `isNotNull(stopEvents.endAt)`,
    `gte(stopEvents.startAt, new Date(startMs))`, `lt(stopEvents.startAt, new Date(endMs))`.
    Order by totalSeconds DESC.
  - Do NOT compute cumulative % in SQL (RESEARCH anti-pattern). Return raw rows
    `{ reason, stopType, incidentCount, totalSeconds }[]`; the page enriches cumulative % in JS.

(2) `getBalesPerDayData(plantId: number, fromDate: string, toDate: string)`:
  - Bounds as above. Group baleEvents by Oslo calendar day and fraction.
  - Derive the Oslo day key in SQL is awkward (UTC stored); instead fetch raw bale rows
    `{ occurredAt, fractionId }` joined to fraction name in [startMs, endMs] for tenant+plant,
    then group in JS: compute Oslo date string per row via
    `new Intl.DateTimeFormat('en-CA', { timeZone: 'Europe/Oslo' }).format(occurredAt)`.
  - Return long format `{ osloDate: 'YYYY-MM-DD', fractionId, fractionName, count }[]`
    plus an ordered `fractions: { id, name, sortOrder }[]` list (so the chart can pivot to wide
    format and assign stable colors/order). Keep the pivot-to-wide in the page (Plan 03), not here.

(3) `getDayVsEveningComparison(plantId: number, fromDate: string, toDate: string)`:
  - Reuse `getShiftReportList(plantId, fromDate, toDate)` internally (it already computes per-shift
    OEE via calculateOee — keeps everything consistent). Reduce its rows in JS, bucketed by shiftType
    ('day' | 'evening'):
    `{ shiftType, shiftCount, avgOee, avgAvailability, avgPerformance, avgUptimePct,
       totalBales, totalStopSeconds, totalStopCount }`.
    avgUptimePct = sum(runSeconds)/sum(plannedSeconds) across that shiftType (weighted, not mean of
    ratios). Return an array of (up to) two rows.

(4) `getShiftEnergyProxy(plantId: number, shiftId: number)`:
  - Find the bunker machine (`eq(machines.type, 'bunker')`, tenant+plant), limit 1. If none → null.
  - Fetch the shift row (tenant+plant scoped) to get startAt/endAt; if none → null.
  - Select `avgCurrentA: sql<number>\`round(avg(${timeSeriesReadings.currentA}), 2)\`` and
    `readingCount: sql<number>\`count(*)\`` from timeSeriesReadings where machineId = bunker.id,
    tenant scoped, recordedAt in [shift.startAt, shift.endAt).
  - Return `{ avgCurrentA: number | null, nominalCurrentA: number | null, readingCount: number }`.
    The page renders the "indikasjon, ikke kWh" label (SHFT-01 energy indication).

Export interfaces: `ParetoRow`, `BalesPerDayRow`, `ShiftComparisonRow`, `ShiftEnergyProxy`.
  </action>
